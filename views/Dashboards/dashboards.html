How it's built

  • Sources: completion-system exports (subsystems, ITR-A/B/C, punch, certificates) refreshed weekly.
  • Model: star schema with a system → subsystem hierarchy, a shared date table and a Friday week-ending key, so every page cuts off on the same day.
  • Status mapping: raw statuses are normalised in Power Query (e.g. “Complete” → “Completed”, not-issued items → “Outstanding”) so totals reconcile across contractors.
  • Pages: overall summary for management, one page per package or area, punch origin, equipment outstanding and manpower demobilisation.
  • Kaynaklar: tamamlama sisteminden haftalık yenilenen dışa aktarımlar (alt sistemler, ITR-A/B/C, punch, sertifikalar).
  • Model: sistem → alt sistem hiyerarşisi, ortak bir tarih tablosu ve Cuma hafta-sonu anahtarı olan yıldız şema; böylece her sayfa aynı günde kesilir.
  • Durum eşleştirme: ham durumlar Power Query’de standartlaştırılır (ör. “Complete” → “Completed”, yayımlanmamış kalemler → “Outstanding”); böylece toplamlar yükleniciler arasında tutarlı olur.
  • Sayfalar: yönetim için genel özet, her paket veya alan için bir sayfa, punch kaynağı, eksik ekipmanlar ve personel demobilizasyonu.

Week-ending key (calculated column)
Week Ending =
'Date'[Date] + MOD ( 6 - WEEKDAY ( 'Date'[Date], 1 ), 7 )
Cumulative certificates signed
CCC Signed (Cum) =
CALCULATE (
    COUNTROWS ( Certificates ),
    Certificates[Type] = "CCC",
    Certificates[Status] = "Completed",
    FILTER ( ALL ( 'Date' ), 'Date'[Date] <= MAX ( 'Date'[Date] ) )
)
