What the finished app does

Reads your ride data

A GPX or FIT file from Strava, including heart rate, speed, distance, elevation and gradient.

Syncs automatically

Reads the date and time the SJCAM camera prints in the corner of the picture, so video and data line up without manual work.

Draws the overlay

Heart rate with a colour-coded zone, speed, distance, elevation, gradient, elapsed time, an elevation profile and a route map.

Makes two lengths

The full ride, or an automatic highlight reel: top speed, max heart rate, climbs, sprints.

Makes two shapes

YouTube/MP4 at 16:9, or an Instagram Reel at 9:16.

Adds music

Optional background music, with separate volume for the music and the camera sound.

Opens from the desktop

A shortcut starts it in your browser, ready for every new ride.

How it works

Two files go in, a finished video comes out. Each box is one of the Python files Claude wrote.

Ride videoMP4 straight from the SJCAM memory card
Strava fileGPX, or .fit via Export Original
Syncsync.pyReads the on-screen clock with OCR and works out the time zone
Telemetrytelemetry.pyOne row per second: speed, gradient, heart rate, distance
Highlightshighlights.pyScores every second and picks the clips
Overlayoverlay.pyData panel, elevation profile, route map, title card
Renderrender.pyFFmpeg crops, overlays, encodes, joins clips, mixes music
Finished videoFull ride or highlights · 16:9 or 9:16
Around it all: app.py, a browser interface built with Streamlit where you pick a folder, preview, choose options and render. RideVideo.bat starts it.

Step by step

The conversation

The whole app came from five short messages. Claude did the planning, installing, coding and testing in between. Send them in this order and answer Claude's questions as they come.

  1. 1

    Describe the idea and ask what's needed

    You
    I want to create an app for myself. I will upload my videos from my cycling rides and GPX files from Strava. It will either create a short version of highlights or full video. What do we need?
    Claude
    Replies with a plan (inputs, time sync, highlight detection, overlays, rendering), a suggested tech stack and a few questions.
  2. 2

    Answer the questions and ask it to set up your PC

    You
    I use SJCAM. I need data overlays, I need heart rate. Output should have options: mp4 or Instagram. I may need background music, it is optional. This is not a one-time thing, I will do this multiple times. Check the required apps; if they are not installed, install them.
    Claude
    Checks for Python, FFmpeg, Git and your graphics card, tests hardware video encoding, and installs what's missing in a separate Python environment.
  3. 3

    Give it a real sample ride

    Copy one video and its GPX into the project folder, then say:

    You
    I uploaded a video and GPX file inside the folder, as an example.
    Claude
    Reads the files' details (length, resolution, timestamps, heart rate) and reports anything odd. Here it found the video's file date was wrong because the clip had been through an editing app.
  4. 4

    Show it the camera's timestamp

    Paste a screenshot of the date/time printed on the video and say:

    You
    I have a time stamp on the video.
    Claude
    Grabs frames from the start, middle and end, installs Tesseract OCR, and confirms it can read the stamp. From this it works out the camera's time zone and the exact offset to the GPX.
  5. 5

    Ask it to build

    You
    Yes, build it.
    Claude
    Writes the app module by module and tests each part on your sample as it goes: ride data, sync, overlay previews in each format, highlight picks, test renders, the browser app itself and a desktop shortcut. It shows you preview images along the way and fixes layout problems it spots.
When it finishes, Claude tells you how to use the app, what it tested and what it did not test. Read that last part; those are the first things to try yourself.

Tips for good results

The biggest win is giving Claude real files early. It tests against them and catches problems a description never reveals.

Start with the goal, not the code

"What do we need?" gets you a plan and the right questions before anything is built.

Say how often you'll use it

"Not a one-time thing" led to a reusable app with saved settings and a desktop shortcut, rather than a one-off script.

Hand over a sample

One real video and GPX let Claude find the wrong file date, the 1–2 second GPS gaps and the 720p resolution before writing code.

Share screenshots

One picture of the on-screen timestamp replaced a manual sync step with automatic sync.

Ask for previews

Claude can render still frames of the overlay; ask to see them before a long render.

Ask what wasn't tested

Claude lists it at the end; check those yourself first.

One change per request

"Make the speed number bigger" works better than five changes in one message.

Interrupt if it's going wrong

Type a correction while Claude is working; it adjusts without starting over.

Troubleshooting

Most problems come from the camera clock, the source file or a missing tool. Tell Claude the symptom and paste any error, and it can fix the code.

Numbers lag or lead the picture
CauseCamera clock a few seconds offFixMove the Fine-tune sync slider in the app
"Couldn't read the clock stamp"
CauseDate stamp switched off, or a very bright scene behind itFixTurn the stamp on in camera settings; type the start time in the box the app shows
Video is a day or hours out
CauseWrong time zone guessFixSet Camera time zone by hand (e.g. 3 for UTC+3)
No heart rate shown
CauseGPX exported without heart rateFixUse Strava's Export Original (.fit)
Instagram version looks soft
Cause720p source, cropped and enlargedFixUse the "full picture + data panel" format, or record at 1080p or higher
Render fails straight away
CauseHardware encoder not availableFixSet Encoder to Software in the sidebar
Browser page is blank
CauseApp still startingFixWait 10 seconds and refresh
Anything else
FixSend Claude the file last_render.log from the output folder
